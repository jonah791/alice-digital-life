# 自主循环智能体 · 最小可行方案（Autonomous Circular Agent — MVP）

> 一个「最小可行」的自主循环智能体架构：**循环 = 存在本身**，无心跳、无巡检、无外部调度。
> 状态：已在 DeepSeek Harness (DSH) 上完整实现并实战验证（2026-08-15）。

## 一、定义

| 层次 | 定义 | 本方案的落点 |
|---|---|---|
| 循环智能体 | 7x24 持续运行；不归零记忆、物理时钟感知、异常免疫、终局判定 | 四条件全部具备 |
| 循环进化智能体 | 运行时修改自身 Harness（框架/插件） | 手术刀路径（热重载+沙盒预检） |
| 自主循环进化智能体 | 自主决定进化时机、休眠节奏、资源压缩、目标重排 | 一切决策归智能体 |

## 二、核心原则

**框架/插件是器官与工具，决策归智能体。**

- 任何「自动」机制只保证：**不丢、知道、兜底**
- 机制把信号送达（inbox 通知），不代替决策（写死规则 / 自动重启）
- 每次自主决策必须写 reason（决策日志/记忆），可追溯
- 睡眠是「我选择不在场的时间」，不是停机；醒来是「我回来了」，不是被叫醒

## 三、最小闭环

    while (true) {
      醒来（输入 / sleep 到期自我唤醒）
      → 感知（睡了多久 / 期间变化 / 事故记录）——时间感来自差值
      → 工作（响应 / 自主任务）
      → 决策（继续 / 睡多久 / 压缩 / 进化——理由可追溯）
      → sleep(ms)   // 可打断：主人消息随时唤醒
    }

**验收标准（最小）**：

1. 智能体自主决定睡 2 分钟 → 到期自我唤醒 → 感知差值时间感 → 继续工作（零外部调度）
2. 睡眠期间任何输入可打断（到期时若已有输入则不再自我唤醒）
3. 每次睡眠决策落盘（时间/时长/理由）

## 四、原语三件套（框架只提供这些）

| 原语 | 职责 | 边界 |
|---|---|---|
| sleep(ms) | 可打断进程内 wait，到期自我唤醒，醒来消息携带差值时间感 | 不回答「睡多久、醒后做什么」 |
| 记忆保底 | 压缩/重要事件 → 原文存档 + inbox 通知（排队不唤醒） | 不替智能体决定「提炼成什么」 |
| 免疫兜底 | 崩溃恢复 + 变更沙盒预检（失败不 kill 旧实例，零中断） | 只保不死，不替智能体做日程 |

## 五、自主边界（信任授权）

| 级别 | 范围 | 门控 |
|---|---|---|
| 自主 | 插件层改动、文档、配置值 | 预检 + 测试 + 决策日志 |
| 请示 | 核心引擎手术、官方库替换 | 主人确认 |
| 禁区 | 删数据、凭据、金额 | 永不自动 |

哨兵门控 + 沙盒预检 + 自动唤醒——变更隔离的参考实现见 [gatekeeper/](gatekeeper/)（守护脚本 + 预检脚本 + 部署与失败行为说明）。

## 七、实测证据（2026-08-15）

- 生命循环首测：life_sleep(2min) → 决策日志落盘 → 到期自我唤醒（差值时间感：睡了 2 分钟，期间新增 100 条事件）→ 醒来继续
- 睡眠可打断：主人消息唤醒 → 旧 timer 到期检测到已打断 → 不重复唤醒
- 免疫沙盒：插件变更先试运行验证，两次真实事故（依赖未装 / schema 不支持）被挡在门外，web 零中断
- 记忆联动：压缩完成 → 保底存档 + 通知排队 → 智能体自主决定提炼

## 八、局限与演进

- 物理时钟感知依赖宿主进程存活（进程重启后由免疫层恢复，跨进程不连续）
- 「自主进化」目前由智能体自觉触发（提案机制）——完全自动化的进化信号扫描是下一步
- 本方案是**架构契约**，不绑定 DSH——任何支持「可打断 wait + 事件溯源 + 插件热载」的宿主都可复刻
